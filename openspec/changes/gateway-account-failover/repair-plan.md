# 网关账号故障切换修复方案

[现有验收底表](verification.md)

## 请求决策

1. 检查客户端取消、语义输出、绑定透传与明确停止指令。符合原账号重试条件时显式携带账号 ID，重新验证当前分组、模型和资格，取得实际账号槽后向原账号发送。此处沿用账号重试次数与请求预算。原账号资格失效或重试耗尽时，按跨账号规则重新选号。
2. 把普通上游错误、OAuth 403 重试耗尽及持久传输错误的账号状态写入登记到请求级收集器。替代账号通过路由、利润、取槽和发送预算检查时，提交上一账号适用的动作。请求取消、语义输出、无备选和预算拒绝发送时丢弃。按账号和受影响范围去重。
3. 在鉴权后安装策略快照，按实际分组缓存读取，合法回退分组独立解析。保留显式 false/0 以及全局和旧配置回落。

## Redis 冷却和成本账本

- 在启动装配注入分组策略仓储和 Redis 冷却仓储。选号按请求、实际分组和模型复用批量快照。真正单账号组保持零额外查询。取得真实槽并通过利润终检后领取半开租约。忙时释放槽并有限重选，Redis 故障时放行。完成探测时保护租约代际。汇总请求实际失败后决定跨请求冷却，多个账号同败时抑制新增冷却。
- 在现有实际发送入口用服务端执行 UUID 和发送序号记录成本尝试。将观测结果交给独立有界队列。未知用量记为 NULL，停机时限时排空，保留用户计费事务与去重键。

## 预算契约与验收

预算耗尽沿用原状态映射和 `X-Failover-Reason: budget`，公开正文隐藏 `attempts`，内部保留准确次数。非预算终局保留现有响应。`Retry-After` 沿用各协议现有规则。

定向测试覆盖双账号中同号重试与随后换号、终止时零账号写入、原预算响应、分组覆盖、冷却半开及重选、成本审计与用户扣费隔离。最后逐条执行 build、vet 和普通及 unit 两档完整全仓测试，记录退出码及未通过项。
