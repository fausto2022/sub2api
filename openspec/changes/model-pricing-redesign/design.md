# 模型价格配置重构 + 模型广场 设计方案

> 版本：v2.0 · 2026-11-15
> 状态：待用户确认后实现

## 0. 需求还原与交互评估

### 0.1 用户原始诉求（拆解为 6 条）

| # | 诉求 | 类型 |
|---|---|---|
| R1 | 取消「内置价格 / 人民币口径」Tab 选择，单页直接按类型/关键词搜索模型 | 交互化简 |
| R2 | 编辑弹窗内「一键转人民币」快速换算填充 | 交互化简 |
| R3 | 支持在本页直接新增模型 | 能力补齐 |
| R4 | 替代原有「渠道定价」 | 架构调整 |
| R5 | 高峰价 / 低谷价勾选式开关，开启后填对应价格 | 能力补齐 |
| R6 | 价格面向所有用户开放 → 模型广场；按分组展示不同模型价格与分组倍率 | 对外能力 |

### 0.2 交互是否更简单：结论

**是的，但简化的是「操作路径」，代价是「概念密度」上升。** 逐项评估：

| 诉求 | 是否更简单 | 判断依据 |
|---|---|---|
| R1 取消 Tab | ✅ **明显更简单** | 现状两 Tab 之间是「同一模型的两种计价表达」，用户必须在脑中维护映射。合并后单列表 + 行内编辑，符合"一个模型一张卡"心智 |
| R2 一键转人民币 | ✅ **更简单（需去歧义）** | 消除跨 Tab 重复录入模型名；但方向必须显式（见 0.3 歧义 1） |
| R3 单页新增模型 | ✅ **明显更简单** | 现状新增要先建渠道 → 再配渠道定价 → 再回价格页，3 跳 |
| R4 替代渠道定价 | ⚠️ **不是纯简化，是职责重划** | 渠道定价兼「用户售价」与「上游成本锚点」两职；直接删会导致利润控制失效（见 0.3 歧义 2） |
| R5 高峰/低谷双价 | ⚠️ **表达更直观，但语义要定死** | 现状 DeepSeek 峰谷是**代码内写死倍率**（2×，UTC 时段）；改成可配置双价必须说明"倍率 vs 绝对价"两种语义并存时谁优先 |
| R6 模型广场 | ✅ 复用现有 `ModelPlazaService` | 已有分组/倍率/官方参考价骨架，主要是入口与开放程度调整 |

### 0.3 一个必须澄清的歧义：**「一键转人民币」= 折算还原，不是口径切换**

> **2026-11-15 用户澄清后定稿**。此前设计把它误解为「输入单位切换」，是错的。

**真实需求**：内置价格表里的国产模型价，是 LiteLLM 用 `¥官方价 ÷ 7.14` 换算来的美元价。例如：

```
DeepSeek 官方价 ¥2 / 1M
  → 内置价格表按汇率折算：2 ÷ 7.14 = 0.28 ≈ $0.30 / 1M   ← 编辑框里看到的 0.3
  → 但本店充值口径是「1 元人民币 = 1 美元余额」
  → 用户充 ¥2 得 $2 余额，却只需付 $0.3 用量 → 亏 6.7 倍
```

**正确做法**：把折算过的美元价 **按汇率还原成人民币原价，再直接当美元价使用**：

```
0.3 × 7.14 = 2.142   →   填回输入框，保存为 $2.142 / 1M
```

这就是用户说的「输入价 0.3，一键转成 2.14」。

**交互定义（单一按钮，不做单位切换）**：

```
编辑抽屉底部（所有模型都有，不区分国产/海外）：
  [⇄ 按汇率还原人民币价（×7.14）]        ← 一键把 4 个基础字段 + 峰谷字段同时换算

点击后：
  输入价 0.3     → 2.142
  输出价 1.2     → 8.568
  缓存读 0.006   → 0.04284
  缓存写 0       → 0（0 保持不变）
  出现提示条：「已按汇率 7.14 还原为人民币原价，保存后按新价计费」
  出现 [撤销还原] 按钮，可回退到点击前的值
```

**关键约束**：

| 约束 | 说明 |
|---|---|
| 作用于所有模型 | 用户明确要求「所有模型打开编辑都有这个功能」，不按平台过滤（海外模型用不到就不点） |
| 只换算非零字段 | `0` 保持 `0`，避免把「未配置」变成「配了 0 以外的值」 |
| 一次性动作，不是持久模式 | 点击即改输入框数值，保存后落库为普通 USD 覆盖；不引入任何「模式」状态 |
| 可撤销 | 提供「撤销还原」回到点击前，防止误点 |
| 汇率取自当前口径设置 | `convert` 用 `cny_per_usd`（默认 7.14）；`direct` 已在 1:1 口径下，按钮置灰并提示「当前已是 1:1 口径，无需还原」 |
| 同时覆盖峰谷字段 | 高峰价、低谷价两组同样换算，保持相对关系 |
| 只读预览保留 | 每个字段下方继续显示 `≈ ¥x.xx`，作为换算后的核对 |

**与「人民币口径（direct/convert）」的关系**：两者独立。
- 口径设置（全局）：决定「人民币登记价如何换算成美元」→ 影响 `cny-overrides.json` 那一层
- 一键还原（单次）：把**已经存在美元价**乘以汇率写回美元价 → 影响 override 层

### 0.4 第二个歧义：「替代渠道定价」的边界


渠道定价当前有双重身份：
1. **用户售价**（`PricingSourceChannel` 参与计费）
2. **上游成本锚点**（利润控制 `账号倍率 ≤ 下游倍率 ×(1-毛利率-缓冲)` 依赖它）

**方案：不删除，改为「模型目录价（Catalog Price）」新层，优先级最高。**

```
新解析链（用户售价）：
  模型目录价（本页配置，DB/文件）  ← 新增，最高优先级
     ↓ 未命中
  分组逐模型定价（group.model_pricing）
     ↓ 未命中
  渠道逐模型定价（channel.model_pricing）   ← 保留，同时继续作为成本锚点
     ↓ 未命中
  人民币登记（换算后）
     ↓ 未命中
  LiteLLM 目录 → Go 兜底表
```

- 管理端「模型价格」页写入 → **模型目录价**
- 渠道页的渠道定价保留不动，继续服务成本核算与历史配置
- 新增设置项 `catalog_pricing_authoritative`（默认 true）：false 时退回旧优先级，作为回滚开关
- 利润控制显式标注：**成本锚点仍读渠道定价**，不改语义

### 0.5 R5 峰谷价的语义定义

现状：DeepSeek 峰谷 = 代码常量（低谷价 × 2 = 高峰价，UTC 01-04 / 06-10 工作日）。

方案：引入**模型级峰谷双价**，与现有机制共存，优先级明确：

| 配置 | 生效方式 |
|---|---|
| 未开启峰谷（默认） | 沿用现状：目录价/官方倍率 |
| 开启「自定义峰谷」 | 低谷价 = 填写的「谷价」；高峰价 = 填写的「峰价」；**时段沿用全局设置**（默认 DeepSeek 官方时段，可改） |
| 只填峰价、谷价留空 | 峰价生效，谷价回落目录价 |
| 只填谷价、峰价留空 | 谷价生效，峰时 = 谷价 × 2（保持官方倍率语义） |

时段配置（全局，一次设置所有模型共用）：
- 高峰时段：多时段列表，默认 `01:00-04:00, 06:00-10:00`（UTC，工作日）
- 时区：默认 `Asia/Shanghai`，周末是否低谷：默认是
- 存 `settings` 表 `peak_pricing_settings`（JSON）

**计费幂等性要求**：模型目录价 + 峰谷双价必须与 DeepSeek 官方倍率**互斥**，避免双重放大（有专项测试）。

### 0.6 R6 模型广场口径

现状：`ModelPlazaService.ListGroups` 已按分组聚合，含 `rate_multiplier`、`peak_rate_multiplier`、`image/video` 独立倍率、官方参考价。当前受 `model_plaza_enabled` 开关控制（默认 false）。

方案：
- 模型数据源改为**模型目录价优先**（与管理端所见一致），官方参考价保留为对照。
- 展示四列：**目录价（USD/1M）**、**分组倍率**、**折后价**（目录价 × 倍率）、**官方参考价**（灰字）。
- 分组维度：顶部按分组切换/分区展示（沿用现有 `PlazaGroupSection`）。
- 开关默认改为 **true**（用户要求"面向所有用户开放"），但保留设置项可关闭。
- 未登录可见（受 `model_plaza_require_auth` 控制，默认 false = 公开）。

## 1. 功能结构

```
管理端 · 模型价格（/admin/model-pricing）   ← 重构为单页
├─ 顶部工具条
│   ├─ 搜索框（模型名 / 供应商 / 平台，防抖 300ms）
│   ├─ 筛选：平台 ▾ · 来源 ▾（目录/人民币/覆盖/自定义） · ☐ 仅看已自定义
│   ├─ [新增模型] 按钮
│   └─ 刷新 / 模型统计（共 N 个，已自定义 M 个）
├─ 主表格（单列表，无 Tab）
│   ├─ 列：模型 · 平台 · 输入$ · 输出$ · 缓存读$ · 缓存写$ · 峰谷 · 来源 · 操作
│   ├─ 行内：编辑 / 恢复内置 / 删除（仅自定义模型）
│   └─ 分页（服务端）
├─ 编辑抽屉（侧滑，替代弹窗，容纳更多字段）
│   ├─ 模型信息（名称/平台/来源徽标）
│   ├─ 顶部操作：[⇄ 按汇率还原人民币价]（一次性 ×汇率写回，可撤销）
│   ├─ 基础价 4 项：输入 / 输出 / 缓存读 / 缓存写
│   │   每项右侧灰字「≈ ¥x.xx」实时换算
│   ├─ 峰谷定价（折叠面板）
│   │   ├─ ☐ 启用自定义峰谷价
│   │   └─ 开启后：高峰价 4 项 + 低谷价 4 项（未填自动回落）
│   ├─ 高级字段（折叠）：图片输入/输出、优先队列、按次价、长上下文阶梯
│   └─ 底部：保存 / 恢复内置 / 取消
└─ 峰谷时段设置（齿轮，全局）
    └─ 时段列表 + 时区 + 周末低谷开关

用户端 · 模型广场（/model-plaza）
├─ 分组切换（Tabs 或锚点）
├─ 每个分组：倍率徽章（含高峰倍率/图片视频独立倍率）
└─ 模型表：模型 · 目录价 · 分组倍率 · 折后价 · 官方参考价
```

## 2. 交互流程

### 2.1 主流程：搜索 → 编辑 → 保存

```
进入页面（无 Tab，直接是列表）
  → 输入 "deepseek" → 300ms 防抖 → 服务端过滤 → 列表刷新
  → 点某行「编辑」→ 右侧抽屉滑出
  → 修改「输入价」= 0.3
      · 字段下方灰字实时更新：≈ ¥2.14
  → 点「⇄ 按汇率还原人民币价（×7.14）」
      · 输入价 0.3 → 2.142，输出价 1.2 → 8.568（4 个基础字段一并换算）
      · 出现提示条「已按汇率还原，保存后按新价计费」+ [撤销还原]
  → 展开「峰谷定价」→ 勾选「启用自定义峰谷价」
      · 出现「高峰价」「低谷价」两组输入
  → 保存 → PATCH → 后端原子写 override_file + 热重载
  → 表格该行立即显示新价 + 「自定义」徽标
```

### 2.2 新增模型流程

```
点「新增模型」
  → 抽屉打开（空表单）
  → 模型名必填 + 平台必选（下拉：openai/anthropic/gemini/deepseek/...）
  → 填价 4 项（可用人民币录入）
  → 保存 → 后端校验：模型名格式、平台合法性、价格范围
      · 若与目录已有模型重名 → 提示"该模型已存在，是否转为覆盖？"（转编辑态）
  → 写入 override_file 并热重载
  → 列表刷新，该行标记「自定义」
```

### 2.3 一键还原人民币价（「换算还原」按钮）

**只有两个触点，语义清晰**：

| 触点 | 行为 | 是否改价 |
|---|---|---|
| 每个字段下方灰字 `≈ ¥2.14` | 实时计算展示（已实现） | ❌ 否 |
| **「⇄ 按汇率还原人民币价（×7.14）」按钮** | 4 个基础字段 + 峰谷字段一次性 `× 汇率` 写回输入框 | ✅ 保存后改价 |

**触发规则**：

- 位置：编辑抽屉底部、保存按钮上方，**所有模型都有**（不按平台过滤）
- 换算对象：输入价、输出价、缓存读、缓存写、高峰价、低谷价（共 6~10 个值）
- `0` 值保持不变（不把「未配置」变成「配了非零值」）
- 点击后显示提示条：「已按汇率 7.14 还原为人民币原价，点保存后按新价计费」
- 提供 `[撤销还原]` 回退到点击前
- 当前口径为 `direct`（1:1）时按钮置灰，提示「当前已是 1:1 口径，无需还原」
- 汇率取当前口径设置的 `cny_per_usd`（默认 7.14）

### 2.4 峰谷勾选交互细节

```
☐ 启用自定义峰谷价
   ↓ 勾选后展开
┌ 高峰价（USD / 1M）          低谷价（USD / 1M）
│ 输入 [____] 输出 [____]      输入 [____] 输出 [____]
│ 缓存读 [__] 缓存写 [__]      缓存读 [__] 缓存写 [__]
└ 提示：留空项按「低谷=目录价、高峰=低谷×2」回落；时段在右上角齿轮配置
```

校验：
- 高峰价 ≥ 低谷价（否则提示"高峰价应不低于低谷价"，允许保存但黄条警告）
- 谷价留空 + 峰价填写 → 允许（回落语义）
- 峰谷开启且模型在 DeepSeek 官方倍率名单内 → 显示提示"将停用官方倍率，改用你的自定义价格"

## 3. 数据与存储设计

### 3.1 模型目录价（新增）

复用现有 `pricing.override_file`，**扩展字段**（不新增表）：

```json
{
  "deepseek-v4-flash": {
    "input_cost_per_token": 3e-07,
    "output_cost_per_token": 1.2e-06,
    "cache_read_input_token_cost": 6e-09,
    "cache_creation_input_token_cost": 0,
    "_catalog": {
      "platform": "deepseek",
      "custom": true,
      "cny_source": true,
      "peak_enabled": true,
      "peak": {
        "input_cost_per_token": 6e-07,
        "output_cost_per_token": 2.4e-06
      },
      "off_peak": {
        "input_cost_per_token": 3e-07
      },
      "updated_at": "2026-11-15T16:00:00Z",
      "updated_by": 1
    }
  }
}
```

- `_catalog` 为元数据命名空间，**以 `_` 前缀避开 LiteLLM 字段解析**（现有解析器跳过未知字段）。
- `custom: true` 表示"该模型由管理员在目录页定义或覆盖"，用于「仅看已自定义」筛选与"恢复内置"判定。
- 若该模型不在 LiteLLM 目录中，`_catalog` 存在即可独立成条（现有 `mergeOverrideOnlyModels` 已支持目录外模型）。

### 3.2 峰谷时段设置（新增）

`settings` 表，key = `peak_pricing_settings`：

```json
{
  "timezone": "Asia/Shanghai",
  "weekday_only": true,
  "weekend_off_peak": true,
  "periods": [
    {"start": "09:00", "end": "12:00"},
    {"start": "14:00", "end": "18:00"}
  ]
}
```

为空时回落内置 DeepSeek 官方口径（UTC 01-04 / 06-10 工作日）。

### 3.3 计价优先级（计费链路）

`model_pricing_resolver.Resolve` 插入新层：

```go
// 新增 PricingSourceCatalog
if catalog := r.catalogService.Get(input.Model); catalog != nil {
    return resolveCatalog(catalog)   // 已含峰谷选择
}
// ... existing group / channel / litellm / fallback
```

峰谷选择在 `BillingService.CalculateCost` 内按请求时刻 `pricingAt` 判定（复用 `deepseekPeakMultiplierAt` 的时段解析逻辑，抽象为 `peakWindowMatcher`）。

### 3.4 模型广场数据

`PlazaModel` 扩展：

```go
type PlazaModel struct {
    Name             string
    Platform         string
    CatalogPricing   *ChannelModelPricing  // 新增：目录价
    Pricing          *ChannelModelPricing  // 原有：实收价（已乘倍率）
    OfficialPricing  *PlazaOfficialPricing // 原有：官方参考价
    PeakPricing      *PlazaOfficialPricing // 新增：高峰价（如有）
    // ... 原有字段
}
```

`PlazaGroup` 增加：
```go
CatalogModelCount int   // 新增：该分组有多少模型来自目录价
```

## 4. 展示逻辑

### 4.1 管理端表格列

| 列 | 内容 | 说明 |
|---|---|---|
| 模型 | 名称 + 平台徽标 + 「自定义」/「¥来源」徽标 | 自定义徽标仅 `custom: true` |
| 输入/输出/缓存读/缓存写 $ | 4 位小数 | `0.3000` |
| 峰谷 | 开启时显示 `峰 $0.6000 / 谷 $0.3000`，否则 `—` | 折叠为两行 |

| 字段 | JSON 键 | 单位换算 |
|---|---|---|
| 输入价 | `input_cost_per_token` | USD/1M ↔ per-token ÷1e6 |
| 输出价 | `output_cost_per_token` | 同上 |

| 缓存写 | `cache_creation_input_token_cost` | 同上 |

| 按次价 | `_catalog.per_request_price` | 直接 USD |
| 长上下文阈值 | `long_context_input_token_threshold` | token 数 |

### 4.3 模型广场展示

| 列 | 计算 | 示例 |

## 6. 迁移与兼容

- **不删旧字段**：`override_file` 里的 LiteLLM 标准字段语义不变，`_catalog` 为新增命名空间。
- **渠道定价保留**：仅新增目录价层，优先级更高；`catalog_pricing_authoritative=false` 可回滚。
- **人民币口径保留**：现有 `cny-overrides.json` 与 `convert/direct` 开关不变，作为目录价之下的一层。
- **迁移脚本**：无需 DB 迁移（仅 settings 新增 key，可运行时写入）。
- **回滚**：删除 `_catalog` 键即回到覆盖语义。

## 7. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 用户误用「一键转人民币」导致价格差 7.14 倍 | 高 | 方向显式标注 + 保存前二次确认弹窗显示"USD $x ↔ ¥y" |
| 目录价与渠道价双重配置导致价格混乱 | 中 | UI 上标注"渠道定价仍参与成本核算"，并在渠道页加提示 |
| 峰谷与官方倍率双重放大 | 高 | 互斥逻辑 + A7 专项测试 |
| 模型广场暴露成本价 | 中 | 仅展示目录价（用户售价），不展示渠道成本 |
| 新增模型平台校验不严导致计费失败 | 中 | 平台白名单校验 + 保存后立即试算一次 |
| 大量模型时列表性能 | 低 | 服务端分页（沿用现有） |
